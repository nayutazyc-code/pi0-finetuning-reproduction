# 环境与版本管理

## 环境边界

- 项目 Python：根目录 `.venv/bin/python`，Python 3.11。
- Python 运行时也保存在项目内：`.runtime/python311`，版本 3.11.16；它是独立的 Conda prefix。
- 不使用 `pip install -e repos/openpi` 安装完整模型项目到 Mac；只安装其中的 `packages/openpi-client`。
- gym-aloha、MuJoCo、dm-control、NumPy 等依赖只安装在当前 `.venv`。
- `.venv` 没有继承其他环境的 site-packages；没有修改全局 Python、Conda base 或先前的学习环境。
- VS Code 配置只作用于本项目文件夹；若历史选择仍覆盖默认值，请手动选一次本项目解释器。

## 环境文件的作用

| 文件 | 管理内容 |
|---|---|
| `.python-version` | Python 次版本 3.11 |
| `pyproject.toml` | 本地包、命令入口及直接依赖 |
| `requirements/macos-arm64.in` | 容易阅读的直接依赖清单 |
| `requirements/build.in` | 本地包和官方客户端 editable 安装所需构建工具 |
| `requirements/macos-arm64.lock.txt` | 当前实际安装的完整版本快照，不含本地 editable 路径 |
| `requirements/environment.json` | Python 精确版本、平台、安装记录与未运行事项 |
| `requirements/python-runtime.osx-arm64.explicit.txt` | Python 运行时的 Conda 制品 URL 与 MD5 |
| `sources.lock.json` | 官方源码 URL 和固定 Git 提交 |
| `.gitmodules` | 管理 `repos/openpi` 这个 Git submodule |

lock 文件固定包版本，但没有锁定每个下载制品的哈希；它用于重建相同版本环境，不是跨所有系统通用的制品证明。

## 重建

已有环境不需要再安装。未来在同类 Apple Silicon Mac 重建时，使用已安装的 Conda：

```bash
PI0_CONDA="$HOME/miniconda3/bin/conda" bash scripts/setup_mac.sh
```

脚本只安装依赖，不自动启动仿真或连接模型。`.runtime` 和 `.venv` 都不是可直接移动的目录；移动项目后应重新创建它们，而不是继续使用包含旧绝对路径的环境。

## Git

根目录已初始化本地 Git，`repos/openpi` 作为固定提交的 submodule 管理。未创建初始提交，也未推送任何远程仓库。

查看本地变化：

```bash
git status
git submodule status
```

不要在 `repos/openpi` 中直接升级后继续使用旧记录。若后续有明确升级需求，应同时更新 submodule 提交、`sources.lock.json`、客户端约定和服务器入口中的提交检查。

环境、模型权重、运行视频、真实观测和本地配置都被 `.gitignore` 排除。个人设置建议复制为 `configs/aloha_sim.local.toml` 并通过 `--config` 指定；SSH 凭据继续使用系统 SSH 管理，不写入项目配置。

## 当前验证范围

完成了源码克隆、依赖安装、版本快照及安装元数据记录。没有运行测试、仿真、窗口渲染、模型推理或训练；这些运行效果尚不能由安装成功推断。

## Mac 启动时报 `No module named pi0_repro`

2026-10-23 排查发现：项目源码和 editable 安装记录均存在，但环境内的 `.pth` 文件带有 macOS `UF_HIDDEN` 标记。当前 Python 3.11.16 的 `site.py` 会跳过这些文件，因此启动时没有加入本项目源码目录。

`scripts/run_mac.sh` 已改为显式加入本项目 `src` 及官方 `openpi-client/src` 两个路径，使用项目自己的 `.venv/bin/python` 启动。该设置只作用于脚本启动的进程，不写入全局 shell 配置。

在 Mac 本地终端重试下面的单行命令：

```bash
cd '/path/to/pi0-repro'
bash scripts/run_mac.sh connect --config configs/aloha_sim.toml
```

本次只处理本地模块查找问题；实际远程连接和仿真仍需云端服务及 SSH 端口转发已就绪。
