# 没有真机，如何采集香蕉抓放成功演示

## 1. 可以全部在仿真里完成

本项目使用 Mac 本地的 MuJoCo、虚拟 ALOHA 双臂和香蕉/盒子场景。脚本专家根据仿真物体位姿和逆运动学生成右臂关节目标，并通过正常物理步进完成抓放。采集过程不加载 π0，不需要真机，也不需要云端 GPU。

演示来源标记为 `simulation_scripted_expert_v2`。它是后续 π0 模仿学习的监督数据来源；专家成功不代表 π0 已经学会这个任务，也不代表真机性能。

## 3. 自己再采一条

在 Mac 终端执行：

```bash
cd '/path/to/pi0-repro'
bash scripts/run_mac.sh collect-demo --config configs/banana_expert.toml --episodes 1 --display
```

显示窗口只负责观察。也可以省略 `--display`，后台推进仿真并保存画面：

```bash
bash scripts/run_mac.sh collect-demo --config configs/banana_expert.toml --episodes 1
```

每次会创建新的 session 目录，不覆盖已有演示。需要中止时按终端 `Ctrl+C`，或关闭实时显示窗口。

`collect-demo --episodes 10` 仍只重复当前固定布局。采集不同摆放位置请使用 `collect-dataset --config configs/banana_dataset.toml`，见 [多布局演示数据集](多布局演示数据集.md)。

## 4. 配置分别在哪里

| 文件 | 作用 |
|---|---|
| `configs/banana_expert.toml` | 抓取深度、夹持目标、移动速度、阶段时间、采集步数上限 |
| `configs/banana_demo_scene.toml` | 物体摆放、质量、摩擦及本次使用的 `position_pd` 场景配置 |
| `configs/banana_pd_pi0.toml` | 后续在同一采集场景里运行 π0 的客户端配置 |
| `src/pi0_repro/banana_expert.py` | 有界逆运动学和分阶段右臂控制 |
| `src/pi0_repro/demonstrations.py` | 同步图像/动作采集、阶段和结果记录 |
| `src/pi0_repro/demo_review.py` | 人工回看后的明确接受或拒绝 |

初期应先使用已采集成功的固定参数，再逐步改变香蕉的位置和朝向。移动到其他位置后仍需重新检查可达性和抓取表现。

## 5. 专家怎样抓取

脚本采用以下顺序：

```text
张开夹爪
→ 到香蕉中段上方
→ 沿竖直方向下降
→ 适度夹紧
→ 抬起并确认两指夹持
→ 搬到盒子上方
→ 放低
→ 主动张开夹爪
→ 退避
→ 等待香蕉稳定
```

右臂以 `cali_right_site1` 为 TCP，使用关节范围内的阻尼最小二乘逆运动学求解目标。所有动作经现有环境的 14→16 执行器适配提交；不会把香蕉的位置直接改成目标位置，也不会把物体焊接到手上。

脚本使用香蕉和盒子的真实仿真位姿，是带有额外几何信息的专家。未来 π0 的输入仍是图像、机器人状态和语言，不把这些真实物体位姿偷偷加入策略输入。

## 6. 本次使用的自定义物理参数

`position_pd` 是为此自定义抓放任务使用的控制/接触模型，具体数值随 `scene.xml` 完整保存：

- 对机器人连杆做重力补偿；香蕉仍受正常重力影响。
- 使用明确的位置增益、关节阻尼和较低的关节干摩擦。
- 原始手指网格用于显示，指腹采用可见的平面 box 碰撞几何体。
- 指腹使用 6 维接触，滑动/扭转/滚动摩擦参数为 `1.5 0.01 0.005`。
- 使用 elliptic 摩擦锥、`impratio=10`、Newton 求解器和 20 次 noslip 迭代，以减少软摩擦造成的持续蠕滑。

这是自定义仿真模型，不是 ALOHA 原版控制参数下的基准结果。后续训练和评估应使用一致的模型；`banana_pd_pi0.toml` 已引用同一份 `banana_demo_scene.toml`。

模型参数定义参见 [MuJoCo 2.3.7 XML 文档](https://mujoco.readthedocs.io/en/2.3.7/XMLreference.html)。

## 7. 保存了哪些文件

```text
session/
  collection.json          # 专家/场景配置、来源、控制周期、源码和场景哈希
  scene.xml                # 实际使用的完整物理模型
  summary.json             # 各次采集结果
  episode_000/
    rgb/000000.png ...     # 第 t 张图像对应第 t 行状态/动作
    trajectory.npz
    steps.jsonl            # 每步阶段、目标、接触和任务状态
    episode.json           # 结果与人工复核状态
    preview.mp4            # 便于回看，末尾额外附最终画面
    terminal.png
    terminal_angle.png
    phase_views/           # 阶段开始时的画面
```

`trajectory.npz` 的字段：

| 字段 | 形状/含义 |
|---|---|
| `state` | `(T,14)`，动作前实际机器人状态 |
| `action` | `(T,14)`，经过执行器范围限幅后实际提交的控制目标 |
| `requested_action` | `(T,14)`，专家原始控制请求 |
| `next_state` | `(T,14)`，动作执行后的状态 |
| `timestamp` | `(T,)`，相对于采集起点的仿真时间 |
| `phase` | `(T,)`，专家动作阶段名称 |

原始训练观测以 `rgb/` 为准，其图像数与动作数一致；不要把视频额外的最终画面也配上一条不存在的动作。

## 8. 如何筛选真正成功的演示

采集器同时要求环境成功、专家计划松爪已发生、且没有中途错误。若搬运或放低时连续失去夹持，会保存失败原因。即便香蕉意外掉入盒子，也不会因此自动作为受控放置演示。

专家采集会在环境已满足成功条件后继续退避和稳定等待，再检查最终状态；普通 π0 评估入口仍默认在成功时结束。

你回看 `preview.mp4` 后确认：没有明显穿透或物体瞬移，夹持和搬运合理，最后确实主动放入盒子并稳定，再运行：

```bash
bash scripts/run_mac.sh review-demo \
  --episode data/banana_demos/20261023-212233-b3dfa8/episode_000 \
  --accept
```

若不合格则执行同样命令但使用 `--reject`。后续采集的路径按实际目录替换。

接受时程序会检查时间间隔、状态连续性、数值和形状、图像数以及计划释放阶段，随后写入：

```json
{
  "human_review": "accepted",
  "eligible_for_training": true
}
```

这一步是由你回看后执行的明确选择。当前样例尚未代你执行接受；后续数据转换应只纳入 `eligible_for_training=true` 的轨迹。

## 9. 从一条演示走向微调

1. 先回看当前候选，确认质量与动作含义。
2. 逐步改变可达范围内的香蕉摆放，采集更多成功演示；现已提供固定种子的多布局采集入口，先覆盖原位置附近。
3. 按完整轨迹/布局划分训练、验证、测试，避免相同轨迹前缀泄漏。
4. 实现固定 LeRobot 版本兼容的转换，再注册 LoRA 配置并计算/选择归一化统计。
5. 云端微调原版 π0，然后把训练配置、权重、统计和 Mac 握手配置一起匹配部署。

LeRobot 转换、训练配置注册和微调部署扩展仍需后续完成；这次完成并实际运行的是仿真专家与同步演示采集。
