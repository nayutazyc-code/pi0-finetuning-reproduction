# 原版 π0 的两个数据接口

## ALOHA：本项目的默认完整仿真入口

观察：

```python
{
    "state": ...,                # float32, (14,)
    "images": {
        "cam_high": ...,         # uint8, (3, 224, 224), RGB
    },
    "prompt": "Transfer cube",
}
```

14 维状态和动作的次序：左臂 6 个关节、左夹爪、右臂 6 个关节、右夹爪。模型输出为未来多个时刻的**绝对关节目标**，不是末端 7 维位姿增量。

默认检查点输出动作块形状为 $H\times14$，此固定配置中 $H=50$。客户端默认执行前 $K=10$ 步，再用新观测请求模型。$H$、$K$、Flow Matching 的积分步数是三个不同概念。

不能把这 14 维动作一律裁剪到 $[-1,1]$；那会改变关节角目标的含义。本项目只检查动作形状与有限值，不改写关节目标。

输入状态不由 Mac 预先做 z-score；服务端使用检查点自带统计完成归一化和输出反归一化。

## LIBERO：单次观测文件接口

```python
{
    "observation/state": ...,        # float32, (8,)
    "observation/image": ...,        # uint8, (224, 224, 3), RGB
    "observation/wrist_image": ...,  # uint8, (224, 224, 3), RGB
    "prompt": "...",
}
```

8 维状态：末端位置 3 维、轴角旋转向量 3 维、夹爪关节位置 2 维。输出动作每步 7 维；具体平移、旋转增量、夹爪指令的坐标系和标度必须匹配 LIBERO 控制器。

你可从匹配环境保存一个 NPZ 观测，字段如下：

| 字段 | ALOHA 文件 | LIBERO 文件 |
|---|---|---|
| `state` | `(14,)` | `(8,)` |
| `image` | RGB 顶部相机，`uint8 H×W×3` | RGB 外部相机，`uint8 H×W×3` |
| `wrist_image` | 不需要 | RGB 手腕相机，`uint8 H×W×3` |
| `prompt` | 可选，NumPy 字符串标量 | 可选，NumPy 字符串标量 |

文件不能包含需 pickle 才能读取的对象数组。

```bash
bash scripts/run_mac.sh infer-file \
  --config configs/libero.toml \
  --observation data/你的真实观测.npz
```

该命令只返回动作并保存 `actions.npy`，不执行动作、不启动 LIBERO 环境。需要先启动原版 `pi0_libero` 服务与 SSH 隧道。

如果从官方 LIBERO 原始观察保存文件，应先依照官方示例处理相机方向：示例中的两路图像在 resize 前均旋转 180°。本文件接口认为图像已经完成该方向校正，不再自动旋转，避免二次旋转。

## 执行循环与延迟

Mac 等待远端动作时不继续调用仿真 `step()`。因此回放中的模拟时间与真实经过时间不同。这适合开始理解模型和仿真接口，但不是已经完成的真机异步实时控制方案。

`episode_000.npz` 的第 $t$ 行对应 $(s_t,a_t,r_t)$：记录动作前状态 $s_t$、实际执行动作 $a_t$ 和该次 step 返回的奖励 $r_t$。视频和数组不是完整训练数据集，异常时视频可能包含未完成动作的最后一帧。
