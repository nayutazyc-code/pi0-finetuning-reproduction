# 用原版 π0 在 Mac 仿真中尝试夹取香蕉

## 当前完成到哪里

已添加香蕉任务环境、原版 π0 远程推理接入、14 维动作到 16 个物理执行器的转换、任务状态与成功判定、运行记录。

**本页的 π0 控制入口尚未在本次执行。脚本专家已另行采到抓放候选，见 [仿真专家演示采集](仿真专家演示采集.md)，不代表 π0 已经学会。** 默认云端权重 `pi0_aloha_sim` 针对传方块任务训练，在香蕉场景上属于新任务尝试。模型接入完成，不代表它已经学会香蕉入盒。

## 1. 先确认场景能够显示

在 Mac 的终端执行：

```bash
cd '/path/to/pi0-repro'
bash scripts/run_mac.sh scene --config configs/banana_demo_scene.toml
```

观察香蕉在桌面上、盒子位置合理，之后关闭预览窗口。物体位置仍在 `configs/banana_demo_scene.toml` 修改。

两个配置的用途：

| 文件 | 用途 |
|---|---|
| `configs/banana_demo_scene.toml` | 物体摆放、质量、摩擦与预览相机 |
| `configs/banana_pd_pi0.toml` | 模型连接、语言指令、episode 步数与动作块执行 |

`banana_pd_pi0.toml` 内部引用 `banana_demo_scene.toml`，因此两种入口使用相同的摆放。

## 2. 在 GPU 服务器运行 π0 服务

如果你之前的服务仍在运行，保持它运行即可。需要重新启动时，在云服务器执行：

```bash
source /root/pi0-repro/env.sh
cd /root/pi0-repro/openpi

JAX_PLATFORMS=cuda \
/root/pi0-repro/openpi/.venv/bin/python \
/root/pi0-repro/serve_pi0.py \
--profile aloha_sim
```

本次新增的是 Mac 场景与客户端代码，仍使用你现有的原版 π0 服务。服务器接收图像、机器人状态和指令；MuJoCo 场景在 Mac 运行。

## 3. 保持 Mac 到服务器的端口转发

你之前已经成功读取服务元数据，继续使用当时的 SSH 隧道或 VS Code 的端口转发，确保 Mac 的 `127.0.0.1:8000` 转到服务器的 `127.0.0.1:8000`。

如果需要新建 SSH 隧道，在另一个 Mac 终端执行：

```bash
cd '/path/to/pi0-repro'
bash scripts/ssh_tunnel.sh 用户名@服务器地址 SSH端口
```

把地址、端口替换成云平台控制台当前提供的值，并保持该终端打开。若 8000 转发已存在，就使用现有转发。

## 4. 确认模型连接，然后启动香蕉任务

在 Mac 的终端执行：

```bash
cd '/path/to/pi0-repro'

bash scripts/run_mac.sh connect --config configs/banana_pd_pi0.toml
```

应返回与你之前一致的模型元数据：`model_family=pi0`、`policy_config=pi0_aloha_sim`、`action_dim=14`、`action_horizon=50`。这只表示连接和配置匹配。

随后执行：

```bash
bash scripts/run_mac.sh run --config configs/banana_pd_pi0.toml --display
```

这次进入的是 **香蕉与盒子的自定义场景**。程序默认执行 1 个 episode，最多 600 个控制步，相当于 12 秒仿真时间；网络等待和计算会让实际耗时更长。

`scene` 窗口的暂停、相机切换等快捷键只属于预览入口。模型控制窗口显示俯视画面，关闭窗口或在终端按 `Ctrl+C` 可以结束运行；若正在等待网络响应，窗口事件可能暂时不能及时处理。

## 5. 程序具体如何控制机械臂

每轮按如下顺序执行：

1. 从俯视相机取得 RGB 图像，缩放补边为 224×224，并排列为 `uint8 (3,224,224)`。
2. 读取左臂 6 个关节角、左夹爪、右臂 6 个关节角、右夹爪，组成 `(14,)` 状态。
3. 加入指令：`Pick up the banana and place it inside the open box.`
4. 发给云端 π0，接收通常为 `(50,14)` 的动作块。
5. 取前 10 步执行，每步推进 0.02 秒仿真时间；之后再次观察并请求动作。

控制转换遵循当前 [openpi 的 ALOHA 接口](https://github.com/Physical-Intelligence/openpi/blob/215abfb217dbac7d5f1273282331b9b1866c0479/src/openpi/policies/aloha_policy.py)：机械臂部分是绝对关节角目标，夹爪是归一化开合量。夹爪命令展开为两个方向相反的物理手指目标，因此模型的 14 个数会转换成 16 个执行器控制量。

本地按模型 XML 中的执行器范围限幅，分别记录模型请求与实际提交的目标。实际关节位置受动力学影响，不一定立刻等于控制目标。

输入仍由俯视图像、机器人状态和语言组成；真实香蕉位姿只用于状态记录和判定成功。场景配置中的 `camera` 只影响预览相机，模型输入固定使用 `top`。

## 6. 你希望在画面里看到什么

期望的操作顺序是：

**张开夹爪 → 移到香蕉上方 → 对准较粗的中段下降 → 合拢 → 抬起 → 越过盒沿 → 移到盒子内部上方 → 降低 → 松爪。**

这些动作由 π0 自行预测，当前代码没有把这条抓取路线硬编码成专家轨迹。如果模型没有对准香蕉、夹不住或没有移向盒子，应结合视频和状态日志分析。

## 7. 如何判断抓住、放入和完成

终端每 10 步打印类似以下字段。下面只是字段示意，不代表已经运行成功：

```text
banana step=... ever_grasped=... inside_box=... released=... stable=... hold=.../25 success=...
```

| 字段 | 判定含义 |
|---|---|
| `ever_grasped=True` | 本 episode 曾出现同一只夹爪两指接触香蕉，且香蕉整体离桌超过 2.5 厘米 |
| `inside_box=True` | 香蕉所有胶囊体及视觉端部都落在盒子内腔范围内，允许 3 毫米接触容差 |
| `released=True` | 当前香蕉未与机械臂几何体接触 |
| `stable=True` | 线速度小于 0.02 米/秒，角速度小于 0.5 弧度/秒 |
| `hold=25/25` | 曾抓起后，完整入盒、脱离机械臂、有盒体接触支撑且稳定，连续满足 25 个控制步 |
| `success=True` | 达到上述抓放与稳定保持条件，结束 episode |

25 步是 0.5 秒仿真时间。`grasped` 是当前步的接触/高度判据，`ever_grasped` 表示之前某一步满足过。该抓取判据是工程近似，仍应回看视频确认；它不是完整的力闭合分析。

完整入盒根据胶囊体端点、半径和盒子局部坐标计算，不仅检查香蕉中心点。几何参数含义见 [MuJoCo 2.3.7 geom 文档](https://mujoco.readthedocs.io/en/2.3.7/XMLreference.html#body-geom)。更换为 mesh 香蕉后，需同步更新判定实现。

奖励只在任务成功时给 1，否则为 0。这用于记录评估结果；当前运行入口没有反向传播或优化器更新，不会因为反复运行而自动训练模型。

## 8. 运行结果在哪里

终端会输出新建的 `outputs/日期-时间-编号/` 目录。

| 文件 | 内容 |
|---|---|
| `episode_000.mp4` | 模型控制过程的俯视视频 |
| `episode_000.npz` | `state`、`requested_action`、`action`、`reward` |
| `episode_000_task.jsonl` | 每个控制步的抓取、入盒、接触、速度与成功判定 |
| `episode_000_latency.jsonl` | 每次远程推理延迟与动作块形状 |
| `summary.json` | 是否曾抓住/抬起、最终是否入盒、任务成功与错误状态 |
| `scene.json`、`scene.xml` | 实际使用的场景配置、判定参数和组装后的模型 |
| `run.json`、`server.json` | 本地环境与配置、服务器元数据 |

NPZ 中的 `action` 是限幅后实际提交的关节/夹爪控制目标，`requested_action` 是云端原始请求；`state` 是动作执行前的实际机器人状态。

这些记录用于排查和评估，还不是完整的微调数据集。视频保存的是处理后的 224×224 观测；正式采集演示时还需要设计完整图像保存、时间索引、数据集格式和质量筛查。

## 9. 如果模型一直抓不到

按这条顺序定位：

1. `connect` 成功，但没有动作日志：查看云端是否正在首次推理编译，或是否报错。
2. 出现 `(50,14)` 动作块且机械臂运动：表示观测、网络、模型输出、执行链路已开始工作。
3. 机械臂移动但 `ever_grasped` 一直为假：检查视频中的对准、夹爪开合、物体尺寸与位置，必要时调整场景。
4. 曾抓住但没有放入：查看后续动作和入盒判据。默认权重针对传方块，可能沿用原任务动作分布。
5. 控制链路工作但新任务持续失败：准备该任务的成功演示，微调原版 π0，并同时匹配训练配置、归一化统计和部署检查点。

当前布局固定，不会因每次 seed 改变而自动随机化物体。需要泛化评估时，应另行加入布局采样和独立测试设置。

若先用遥操作或脚本专家采集演示，应在数据和实验记录中写明来源。专家控制器完成任务，不代表未微调的 π0 已经完成该任务。
