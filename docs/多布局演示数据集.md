# 香蕉入盒：多布局仿真演示数据集

## 当前采集范围

本轮使用 Mac 本地 MuJoCo 和脚本专家采集，不加载 π0，也不需要真机。沿用已成功演示的 `position_pd` 物理模型，只改变初始摆放。

第一批预设 24 个布局，每个布局采集一次。分配在运行前确定：训练候选 16 个、验证候选 4 个、测试候选 4 个。划分由布局决定，不根据轨迹成功与否调整。

| 变化维度 | 第一批范围 |
|---|---|
| 香蕉 x | 0.16–0.20 m |
| 香蕉 y | 0.46–0.50 m |
| 香蕉水平朝向 | 0–20° |
| 盒子 x | 0.11–0.15 m |
| 盒子 y | 0.70–0.74 m |

香蕉初始 z 为 0.045 m，重置后自由落到桌面；盒子底部 z 为 0。颜色、质量、照明和物体类别保持本次配置。该批覆盖原成功位置附近的局部范围，不代表整个桌面的泛化能力。

每个维度用固定种子分层采样：把范围分成 24 段，在每段取一个值后打乱组合。它不是五维笛卡尔网格。随机种子为 `20261023`，完整计划在开始时写入 `collection.json`。

## 运行方式

```bash
cd '/path/to/pi0-repro'
bash scripts/run_mac.sh collect-dataset --config configs/banana_dataset.toml
```

需要实时窗口时增加 `--display`。重复执行同一份配置会重新采相同的 24 个布局，保存到新目录；它不会自动增加布局覆盖，也不要把这些重复布局跨训练/测试划分。

后续改范围或种子时，复制配置并记录新的批次。跨批次合并需要按 `layout_id` 统一去重与划分；不要直接把各批次同名 split 拼起来后宣称无泄漏。

## 文件与对应关系

```text
data/banana_demos/<session>/
  collection.json           # 固定计划、种子、划分、专家配置和代码哈希
  dataset_index.json        # 所有已采轨迹、失败原因、分组计数及未完成布局
  summary.json              # 环境与专家运行结果
  episode_000/
    layout.json             # 请求布局、实际落稳初始姿态、reset seed、XML 哈希
    scene.xml               # 本条实际物理模型，包含物体位置
    episode.json            # layout_id、split、结果、人工复核状态
    trajectory.npz          # 状态/实际动作/请求动作/后继状态/时间/阶段
    rgb/                    # 与动作逐行对应的原始图像
    preview.mp4             # 完整回看视频
    terminal.png
    terminal_angle.png
```

控制频率为 50 Hz。原始图像为 640×480 RGB，机器人状态和动作均为 14 维。动作是关节位置目标及归一化夹爪开合目标，不是末端位姿增量。请勿直接套用 OpenVLA 的 7 维动作定义。

每个 episode 都重建相应场景，再让香蕉自由落稳。场景改变只发生在 episode 初始化阶段；执行抓放时不改变香蕉位姿、不添加抓取焊接约束。

## 失败和成功如何处理

- 保留全部已执行尝试；不因失败重新抽取更容易的布局。
- 成功候选需要真实两指夹持并抬起、计划主动释放、最终完整入盒及稳定保持。
- 搬运或下降过程中提前脱手会记录失败，即使最后碰巧掉入盒子也不作为受控成功演示。
- 所有候选仍是 `human_review=pending`、`eligible_for_training=false`。

回看某条视频后，明确接受或拒绝：

```bash
bash scripts/run_mac.sh review-demo \
  --episode data/banana_demos/<session>/episode_000 \
  --accept
# 不合格时改用 --reject
```

复核会同步更新数据集索引。失败轨迹不会因 `--accept` 而变成成功演示。数据集索引的 `training_ready=false` 表示还没有完成 LeRobot 转换，并不代表接受标记失效。

## 后续如何用于微调

1. 人工回看并接受合格候选；失败数据单独用于分析。
2. 第一批先了解采集覆盖和失败类型，再逐步扩大可达位置、角度或场景变化。
3. 跨批次按布局统一去重和划分，保留独立验证/测试布局。
4. 只在训练划分估计归一化统计并拟合参数；验证划分用于选择训练配置，测试划分留作最终评估。
5. 转为固定 LeRobot 版本接受的格式，再配置原版 π0 的 JAX LoRA 微调。

目前保存的是同步原始演示数据，不能直接把整个目录交给 openpi 训练脚本。LeRobot 转换与微调入口仍需单独实现。
