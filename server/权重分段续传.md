# 原版 π0 ALOHA 权重分段续传

`resume_pi0_download.py` 用于当前 AutoDL 部署，只处理官方 `pi0_aloha_sim` 检查点。已添加脚本，尚未在云服务器执行或测得提速结果。

## 适用情况

已有模型缓存保存在 `/root/pi0-repro/cache/openpi/openpi-assets/checkpoints/pi0_aloha_sim.partial`，大部分文件已下好，只剩某个大文件很慢。

脚本从 Google Storage 获取官方清单和对象版本，保留已有文件前缀，只将未下载的尾部分成 4 段并行获取。临时分段在检查点目录外保存，可以继续上次中断的分段；不会让原版 OpenPI 把分段计入模型下载进度。原文件会保留到新文件的大小及 MD5 校验通过。所有文件校验通过后才将 `.partial` 目录整理为正式缓存。

如果瓶颈是单连接，增加连接可能改善总速度；如果瓶颈是共享总带宽，提速可能有限。4 路连接不代表保证提高 4 倍。脚本使用 Python 3.11 标准库，不新增 Python 依赖，不加载模型或使用 GPU。

## 1. 上传：在 Mac 本地终端执行

SSH 主机和端口以 AutoDL 控制台当前连接命令为准。执行前请将示例中的主机、端口和本地项目路径替换为实际值。

```bash
SSH_PORT=2222  # 示例值，请替换为服务器的实际 SSH 端口。
scp -P "$SSH_PORT" \
  '/path/to/pi0-repro/server/resume_pi0_download.py' \
  user@your-server.example.com:/root/pi0-repro/resume_pi0_download.py
```

## 2. 停止原下载：在云端原下载窗口执行

按一次 `Ctrl+C`，等待原进程退出并出现命令提示符。不要让旧下载与新下载同时写同一个模型文件。脚本会尝试取得 OpenPI 使用的同一个缓存锁；若原进程还持有锁，会直接停止。

## 3. 续传：在云端 tmux 内执行

已经在 tmux 内时直接运行以下命令，不需要再启动另一个 tmux。

```bash
source /root/pi0-repro/env.sh

"$PI0_ROOT/openpi/.venv/bin/python" \
  "$PI0_ROOT/resume_pi0_download.py" \
  --workers 4
```

终端会显示剩余部分的进度和各连接合计的最近下载速度。中断后可用相同命令继续；停止时需等待连接退出再启动下一次。临时合并需要额外磁盘空间，当前这个未完成权重文件通常应预留约 3 GB。

如果下载已经由旧进程完成，脚本只核对正式缓存，不会再从头下载。网络超时或校验失败时会保留已有文件并停止；请保留错误输出。

## 4. 看到全部校验完成后，启动云端服务

```bash
source /root/pi0-repro/env.sh
cd "$PI0_ROOT/openpi"

JAX_PLATFORMS=cuda \
"$PI0_ROOT/openpi/.venv/bin/python" \
"$PI0_ROOT/serve_pi0.py" \
--profile aloha_sim
```

继续等待服务监听 `127.0.0.1:8000`，再通过 SSH 端口转发连接 Mac 仿真客户端。
